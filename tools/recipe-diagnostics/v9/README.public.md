Запустите сборку обычным способом через лаунчер. На обоих компьютерах откройте `Start-RecipeDiagnostics.cmd` и дождитесь `OBSERVER_READY`. Затем хост открывает мир для сети, второй игрок подключается. После ошибки отправьте обычный отчёт через лаунчер.

Лимиты за запуск утилиты: 8 ошибок рецептов, 24 события закрытия, 32 события keepalive и до 24 снимков очередей. Общий объём исходных строк ограничен 256 КиБ. Снимки очередей делаются не чаще одного раза в 5 секунд при обнаруженном активном Steam bridge; перечисляются максимум 16 объектов каждого типа и 32 заголовка потоков. Без поддержки перечисления объектов JVM эта часть диагностики отключается. Поля Netty читаются только после проверки точного SHA его библиотеки.

Снимки читают поля работающего процесса и не являются атомарными: значения могли измениться между чтениями. Отсутствующее поле, объект или неподдерживаемый тип отмечается как неизвестное значение. Нулевая длина очереди не доказывает доставку: счётчик не включает уже извлечённый retry-пакет и данные в других буферах. Максимум объектов может дать неполный список. Утилита не вызывает игровые методы, не изменяет классы и не приостанавливает потоки для периодических снимков; перечисление объектов всё равно создаёт диагностическую нагрузку. Состояния потоков записываются без стеков и содержимого сетевых пакетов.

`clientbound_challenge_constructed` подтверждает создание пакета. `clientbound_challenge_encode_completed` подтверждает завершение записи его ID в буфер кодека. Эти события не доказывают отправку в сокет или доставку. `clientbound_challenge_decoded` подтверждает чтение ID на принимающей стороне; вызов обработчика отмечается отдельно. Ошибка снимка JDI относится к утилите и сама по себе не является исключением игры.

После готовности и каждого события обновляется `logs/recipe-diagnostics-<сеанс>.log.gz`, содержащий только строки утилиты. Он сохраняется после очистки `debug.log`. Отчёт лаунчера выбирает два самых новых файла `logs/*.log.gz`, изменённых за последние 24 часа. Последующие запуски могут вытеснить нужный архив из этой пары; общая очистка журналов также ограничивает срок хранения и объём.

Это временная внешняя утилита. Она не меняет таймауты, дальность прорисовки, настройки сборки или транспорт e4steam. После завершения диагностики её можно удалить вместе с двумя временными параметрами запуска сборки.
