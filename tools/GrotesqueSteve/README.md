# Grotesque Steve: согласованный вариант 1.4.2-quiet.1

Исходник — именно предоставленный пользователем `grotesque_steve-1.4.2-forge-1.20.1.jar`: 22 223 025 байт, SHA256 `7edde5b1506a69a725412769525ba16122b1dd4c38e35f3edc5c015eef3a6f63`. Он хранится в `source/` только для воспроизведения и не устанавливается в `mods`. Другая бесплатная/платная редакция, URL-загрузка или похожий файл не подменяются.

Пользователь согласовал отключение приветствия, двух звуков и автоматической выдачи руководства при входе. Изменены только четыре ZIP-записи:

- `GrotesqueMessageProcedure.onPlayerLoggedIn(PlayerLoggedInEvent)V` сразу возвращается: нет английской action-bar подсказки и двух звуков `wind`/`fart` при входе. Другие применения этих звуков и все аудиофайлы сохранены.
- `AdvancementtriggerProcedure.onPlayerLoggedIn(PlayerLoggedInEvent)V` сразу возвращается: не выдаёт критерии `grotesque_hello` и автоматическую книгу. Другие методы, сама книга, GUI, награда `grotesque_steve:give` и ресурсы сохранены. У достижения два AND-критерия, включая `minecraft:impossible`; один переход между измерениями не завершает его автоматически.
- В `minecraft:manualgiver` убран ровно один недопустимый начальный `/`: функция содержит корректное `give @p grotesque_steve:manualbook`. Эта отдельная исправленная функция не является отключённым login-путём.
- `META-INF/mods.toml` сообщает `1.4.2-quiet.1`, прежний mod ID `grotesque_steve` сохранён. Это локальная производная редакция, не официальный новый релиз автора.

2495 остальных записей, включая модели, текстуры, анимации, способности, конфигурацию, исходный `pack.mcmeta` format15 и все прочие классы, сохраняют исходные payload-байты. В двух изменённых классах меняется только Code соответствующего callback; constant pool, Forge annotations, поля, остальные методы и class attributes сохраняются побайтно. Нового helper-мода или runtime-патчера нет.

Воспроизведение из корня исходников сборки:

```text
python -B tools/grotesque_steve_quiet.py --input tools/GrotesqueSteve/source/grotesque_steve-1.4.2-forge-1.20.1.jar --output OUTPUT/grotesque_steve-1.4.2-quiet.1-forge-1.20.1.jar --report OUTPUT/grotesque-quiet-report.json
```

Нужен только Python3.11+ со стандартной библиотекой. JDK, ASM, интернет и загрузка дополнительных ресурсов не нужны. Неподходящий SHA/размер исходника, class/method SHA, metadata, Code-структура или запись вне whitelist отклоняются. Запись производится атомарно в отдельный выходной файл; исходник не изменяется.

Детерминированный ZIP_STORED с фиксированными временем/атрибутами/create_system и сортировкой исключает различия zlib между Windows и Linux. Результат: 26 240 866 байт, SHA256 `ffa7df6fb07e54217757436b566fa0073b460c5fa4b695cfd2d4d40692208052`. Увеличение контейнера связано с отсутствием повторного сжатия, а не с новыми ресурсами.

Подтверждены повторная побайтная сборка, 13 положительных/отрицательных проверок, Java17 `-Xverify:all` с настоящими классами Minecraft1.20.1/Forge47.4.0, немедленный возврат обоих callback, pack format15 настоящим serializer и обработка `/give` настоящим CommandFunction. Для последней проверки зарегистрирован минимальный Brigadier `give` с greedy arguments; полная игровая item-registry в standalone-процессе не создавалась. Полный клиент после включения производного JAR проверяется отдельно.

## Воспроизводимые тесты

13 проверок запускаются из корня исходников сборки:

```text
python -B -m unittest discover -s tools/GrotesqueSteve -p test_quiet.py -v
```

Тесты используют только исходник из `source/` и действующий `tools/grotesque_steve_quiet.py`. Производный JAR создаётся в новом временном каталоге, затем удаляется. Установленная игра, активный `mods`, персональные настройки и миры для этих тестов не используются.

Настоящие проверки JVM и парсеров запускает отдельный параметризованный стенд:

```text
python -B tools/GrotesqueSteve/run_native.py --java JAVA17_EXECUTABLE --javac JAVAC17_OR_NEWER_EXECUTABLE --classpath-file NATIVE_CLASSPATH_JSON --author tools/GrotesqueSteve/source/grotesque_steve-1.4.2-forge-1.20.1.jar --quiet DERIVATIVE_JAR --out OUTPUT/grotesque-native-checks
```

Имена заглавными буквами заменяются явными путями. Нужны настоящий Java17 и компилятор Java17+; пути не обнаруживаются автоматически. `--classpath-file` — UTF-8 JSON-массив путей к JAR зависимостей настоящего профиля Minecraft1.20.1/Forge47.4.0 либо одна строка classpath с разделителем текущей ОС. В этот список не включают Grotesque и тестовые классы: стенд сам подставляет авторскую или quiet-редакцию для соответствующего случая. Повторы того же пути нормализуются с сохранением порядка.

В classpath обязательны эти точные native-источники:

| JAR | SHA256 |
| --- | --- |
| `forge-1.20.1-47.4.0-client.jar` | `010adc332f19b05fb24383954ec7a88694666216e480a6824ff0cbc4740c3c66` |
| `client-1.20.1-20230612.114412-srg.jar` | `e2e940fe7ca0a9fba5a5c11ad2cf3e2f7df91bbf51d12af22cdde7af18adc344` |
| `forge-1.20.1-47.4.0-universal.jar` | `2b0e97b22fd4d043dbbcc8e0a44ef0d58915689ed9224e4cd28d5c4976a16bcc` |

Остальные JAR берутся из явного classpath того же профиля. Стенд проверяет SHA и первый фактический источник `PackMetadataSectionSerializer`, `CommandFunction` и `PlayerLoggedInEvent`, чтобы другой JAR или stub не подменил нативную проверку. Он компилирует только `NativeQuietProbe.java` с `--release 17` в новый каталог и проверяет, что других `.class` не создано. Game main, GUI, мир, звук и GPU не запускаются.

Оба полных изменённых класса вызываются по точному Forge-дескриптору с null event и должны сразу вернуться. Те же авторские классы в отдельном процессе должны обратиться к null event и дать ожидаемый NPE: это отрицательный контроль, а не настоящая ошибка игрового входа. Оба JAR проверяются настоящим `PackMetadataSectionSerializer`, который должен прочитать format15.

Для `manualgiver` настоящий `CommandFunction` должен отвергнуть исходный `/give` и принять исправленную строку. Минимальная Brigadier-регистрация `give` разбирает оставшиеся аргументы как строку; стенд не создаёт игровую item-registry и не обещает проверку выдачи предмета, разрешений команды или состояния инвентаря. Сама книга и действующая `grotesque_steve:give` проверены отдельно на неизменность байтов.

`native-report.json` рядом содержит очищенный снимок успешной подготовки. Новый запуск пишет свой отчёт под `--out`; stdout/stderr и скомпилированные классы там являются локальной диагностикой и не публикуются. Каталог `--out` должен находиться отдельно от всех неизменяемых входных файлов. Изменение pinned native-версий требует отдельной проверки и не принимается автоматически.

## Статическое доказательство отключения автоматической книги

`autoguide-static-proof.json` фиксирует исходные критерии и точные class/JAR SHA. В `grotesque_hello` нет явного `requirements`: native `Advancement.Builder.m_138380_` в указанном SRG заполняет отдельную singleton-группу для каждого критерия (участок bytecode233–310), то есть требуются оба. `minecraft:changed_dimension` может дать только один; `minecraft:impossible` сам по событию не срабатывает. Раньше login callback явно выдавал все недостающие критерии; теперь именно этот callback возвращается.

`Advancementtrigger3Procedure` не имеет `EventBusSubscriber`, `SubscribeEvent` или других runtime annotations; в нём только конструктор и `execute(Entity)`, class attributes содержит только SourceFile. Статических callers вне собственной class-записи в авторском JAR не найдено. Его наличие не означает оставшуюся автоматическую Forge-подписку. Операторская выдача книги/достижения и динамические внешние команды намеренно не блокируются. Это статическое доказательство авторского пути; наблюдение первого входа в свежий мир является отдельной runtime-проверкой.
